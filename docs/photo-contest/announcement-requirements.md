# 今回の実装対象

フォトコンテストの結果ページではなく、開催前から応募期間中、応募終了後まで継続して利用できる「開催告知・応募案内ページ」を作成します。

初回コンテストの推奨URLは次です。

```text
/photo-contest/2026-01/announcement
```

将来の結果ページは、次のようなURLを想定します。

```text
/photo-contest/2026-01/results
```

`2026-01`は、2026年の第1回コンテストを表す固定識別子です。

同じ年に複数回開催できるように、年度だけをルート識別子として使用しないでください。

将来の例：

```text
/photo-contest/2026-01/announcement
/photo-contest/2026-01/results

/photo-contest/2026-02/announcement
/photo-contest/2026-02/results
```

既存プロジェクトのルーティング規則や、すでに実装されているフォトコンテストページとの競合がある場合は、実装前に問題点と代替案を説明してください。

# ページの利用期間と状態

このページは、開催前だけに使用する一時的なページではありません。

同じURLを次の期間で継続して使用できるようにしてください。

1. 開催予告期間
2. 応募受付期間
3. 応募終了後
4. 結果公開後

ページURLと基本レイアウトは変更せず、開催状態に応じて表示を切り替えられる構成にしてください。

想定状態：

```text
scheduled
open
closed
resultsPublished
```

表示例：

| 状態 | 表示 |
|---|---|
| `scheduled` | 開催決定・近日受付開始 |
| `open` | 応募受付中 |
| `closed` | 応募受付終了 |
| `resultsPublished` | 結果公開済み |

状態は`.tsx`へ直接記述せず、コンテンツファイルから管理してください。

可能であれば、開始日時と終了日時から状態を自動判定できるようにしてください。

ただし、既存のホスティング方式や静的出力の制約により、日時による自動切り替えが確実に機能しない場合は、次のような上書き値をコンテンツ側に持たせてください。

```json
{
  "statusMode": "auto",
  "statusOverride": null
}
```

手動で固定する例：

```json
{
  "statusMode": "manual",
  "statusOverride": "open"
}
```

日時判定を行う場合は、日本時間を基準にしてください。

```text
Asia/Tokyo
```

開始日時：

```text
2026-08-08T00:00:00+09:00
```

終了日時：

```text
2026-08-31T23:59:59+09:00
```

実装方式は、既存プロジェクトのレンダリング方式を確認してから提案してください。

# フォトコンテスト一覧ページからの導線

フォトコンテスト一覧ページ：

```text
/photo-contest
```

一覧ページの各コンテスト項目は、コンテストの状態に応じて適切なページへ遷移させてください。

推奨動作：

| 状態 | 主なリンク先 | CTA例 |
|---|---|---|
| `scheduled` | 告知ページ | 開催概要を見る |
| `open` | 告知ページ | 応募方法を見る |
| `closed` | 告知ページ | 開催概要を見る |
| `resultsPublished` | 結果ページ | 結果を見る |

結果公開後も、告知ページの直接URLは引き続き閲覧できるようにしてください。

コンテスト一覧のデータには、必要に応じて以下を持たせてください。

- 固定ID
- URL用スラッグ
- 年度
- 開催回
- 状態
- 告知ページのパス
- 結果ページのパス
- 結果公開済みか
- 主CTAの文言
- 公開・非公開

URLやリンク先を`.tsx`へ直接記述しないでください。

既存の一覧ページがすでに実装済みの場合は、デザインを壊さず、必要最小限の変更で導線を追加してください。

アニメーションは控えめにしてください。

- リンクの細いラインが伸びるホバー

- 派手なズーム
- スクロールを妨げる演出
- 独自スクロール
- マウスホイールの乗っ取り
- 長すぎるアニメーション
